# Sputnik · спутниковые данные для геологии

Десктопный веб-интерфейс GeologyScience. Каталог продуктов с фильтром по геологическому применению, выбор региона и дат, обзор сцены и скачивание файлов у поставщика. Для прямоугольной области можно использовать карту, её текущий вид или координаты в WGS 84. Готовые регионы задают ориентировочные прямоугольники.

## Запуск

Выполните в корне репозитория. Скопируйте `example.env` в `.env`, задайте длинный случайный `POSTGRES_PASSWORD` и нужный порт на хосте через `SPUTNIK_PORT`.

```powershell
Copy-Item example.env .env
docker compose up --build -d
```

На Linux и macOS для копирования используйте `cp example.env .env`. При настройках из примера сервис откроется по [http://127.0.0.1:18080](http://127.0.0.1:18080). После изменения `.env` примените настройки командой `docker compose up -d`.

Для reverse proxy, работающего непосредственно на хосте, подходит `SPUTNIK_BIND_HOST=127.0.0.1`. Если хостинг требует прямого доступа к опубликованному порту, укажите `SPUTNIK_BIND_HOST=0.0.0.0`. Внутренний порт контейнера — `8080`.

Состояние сервиса показывает `docker compose ps`, журнал — `docker compose logs -f sputnik`. Для остановки выполните `docker compose down`. Данные PostgreSQL остаются в томе `sputnik-db`. Для сборки нужен доступ к Docker Hub, npm и PyPI. При работе контейнер обращается к Microsoft Planetary Computer. Браузер получает подложку OpenStreetMap, предпросмотр и спутниковые файлы непосредственно от поставщиков.

Пример для проверки поиска. Выбрать Sentinel‑2 MSI и «Своя область», ввести запад `132`, юг `43`, восток `133`, север `44`, период с `2025-08-01` по `2025-08-31`. Открыть одну из записей и скачать, например, красный канал `B04`. Облачность в выдаче относится ко всей сцене. Даты в выдаче показаны по UTC.

## Как устроено

- `catalog.py` задаёт поддерживаемые коллекции, геологические теги и пояснения. Один продукт может иметь несколько тегов.
- `app.py` обращается к STAC API. Для Sentinel‑5P ограничивает запрос продуктом SO₂. Для Copernicus DEM выполняет поиск плиток по территории.
- Файлы запрашиваются по идентификатору сцены и ключу ресурса. Python получает короткоживущую SAS-ссылку на Azure Blob, после чего браузер получает файл напрямую.
- Размер файла берётся из STAC или уточняется запросом `HEAD` к хранилищу. Геопривязанное превью использует тайлы поставщика.
- Контейнер приложения stateless. PostgreSQL хранит общие лимиты, сессии, состояние диалога, OAuth state, кэш геокодера и телеметрию. Доступ к каталогу Planetary Computer работает без аккаунта Microsoft.

Проверяемые сведения о продуктах доступны в карточках каталога. Для продуктов без готового изображения, в том числе SO₂, доступны контур наблюдения, метаданные и файлы при наличии ссылки от поставщика. Прямой доступ к OpenStreetMap использует атрибуцию и обычное интерактивное получение тайлов. [Политика использования тайлов OSM](https://operations.osmfoundation.org/policies/tiles/)

## ИИ-помощник

В шапке доступны два режима: «Ручной поиск» и «ИИ-помощник». Один чат соответствует одной исследовательской задаче с общей целью. В задаче может быть несколько объектов; внутри каждого — несколько продуктов. У каждой пары «объект — продукт» собственные область, даты, обоснования и подтверждение. Для сравнения периодов можно добавить один продукт несколько раз. В текущей сессии допускается до 8 объектов и 24 поисков данных; история и контекст восстанавливаются после обновления страницы в той же сессии. «Новый диалог» очищает задачу и объекты, сохраняя использованный лимит.

В центре режима помощника расположен чат с Markdown (списки, выделение, таблицы, ссылки, блоки кода). HTML и загрузка изображений из сообщений отключены. Enter добавляет строку, Ctrl+Enter отправляет сообщение. Пока выполняется запрос, видны спиннер и время ожидания. В правой панели можно выбрать объект и продукт, проверить объяснения выбора, уточнить координаты, изменить даты или радиус. Добавление объекта и продукта, редактирование и подтверждение карточки не обращаются к модели и не расходуют токены.

Небольшая карта показывает подписанные точки объектов и области поисков. Координаты берутся из справочника, ответов геокодеров или пользовательской области; модель не генерирует точки. Круг строится геодезически на WGS 84 с шагом 5° по азимуту. Это область поиска вокруг ориентировочной точки, а не граница месторождения. Можно отдельно выделить прямоугольную область для выбранного продукта. Изменение параметров снимает подтверждение. Кнопка «Найти сцены» переносит подтверждённый поиск в обычную выдачу. STAC запрашивается по охватывающему прямоугольнику, затем записи с нулевым пересечением фактического полигона исключаются; следующие страницы остаются доступны.

Кнопка «Объяснить выбор сцен» заново получает первую страницу STAC, рассчитывает пересечение с фактической областью и передаёт модели только метаданные. Оценка служит предварительным отбором. Геометрический охват и облачность всей сцены — независимые величины; видимость поверхности внутри участка по ним не установлена. Пиксельные маски, изображения и тематические расчёты на этом этапе не анализируются.

Справочная база `knowledge.json` содержит наблюдаемые признаки, применение, ограничения и первичные источники для шести продуктов. При расширении `catalog.py` добавляйте соответствующий профиль в `knowledge.json` и случаи проверки в `assistant-cases.json`.

Для подключения модели заполните `AI_API_KEY`, `AI_BASE_URL` и `AI_MODEL`. Поддерживается OpenAI-совместимый `POST /chat/completions` с JSON-ответом. Для облачного DeepSeek в примере задан `deepseek-flash`. Параметр `AI_REASONING_EFFORT` отправляется только если он заполнен. Проверьте его поддержку при смене поставщика. [DeepSeek API](https://api-docs.deepseek.com/api/create-chat-completion)

### Локальная Ollama

Если Ollama уже работает на хосте Docker Desktop и модель `qwen3.5:9b` установлена, создайте профиль с контекстом 16K. Он использует те же веса. Затем задайте локальные настройки в `.env` и примените их.

```sh
ollama create sputnik-assistant -f ollama.Modelfile
```

```dotenv
AI_BASE_URL=http://host.docker.internal:11434/v1
AI_API_KEY=ollama
AI_MODEL=sputnik-assistant
AI_LOCAL_MODE=true
AI_REASONING_EFFORT=none
AI_TIMEOUT_SECONDS=120
```

```sh
docker compose up --build -d
```

`host.docker.internal` — адрес хоста из контейнера Docker Desktop. Для запущенного непосредственно на хосте Python-бэкенда адрес Ollama будет `http://127.0.0.1:11434/v1`. Значение ключа `ollama` служит заполнителем для совместимого интерфейса. Размер контекста задаётся профилем модели. [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)

Анонимный лимит действует на серверную сессию, ограниченную по времени `SESSION_DAYS`. Новый диалог сохраняет использованный лимит. Дополнительно действуют общая суточная квота анонимов по UTC, предел числа запросов с одной сессии и с сетевого адреса. При размещении за reverse proxy задайте его адрес или CIDR в `TRUSTED_PROXY_NETWORKS`. Только от этих узлов принимается X-Forwarded-For. По умолчанию заголовок игнорируется и учитывается адрес соединения, который за proxy будет общим для его пользователей.

Перед вызовом модели в PostgreSQL атомарно резервируется консервативная оценка входа по числу UTF‑8 байтов, запас на формат сообщений и максимально разрешённый выход. После ответа резерв заменяется данными `usage`. При тайм-ауте или отсутствии `usage` резерв остаётся учтённым, поскольку поставщик мог уже начислить плату. Отказ из-за нехватки резерва возможен раньше исчерпания фактически использованных токенов. Лимиты задаются в токенах и запросах, не являются точной суммой в рублях или долларах. Поле `AI_MAX_PROMPT_BYTES` и ограничение длины сообщения дополнительно ограничивают размер входа.

Пределы сессии и общая квота не применяются к администратору: его обращения не увеличивают счётчики квот сессии, общей суточной квоты и числа запросов с IP. Фактическое использование модели сохраняется в телеметрии всех ролей. Максимальный размер входа и выхода, тайм-аут и один одновременный запрос на сессию действуют для всех.

`AI_MAX_OUTPUT_TOKENS` ограничивает весь ответ модели, включая JSON карточек. По умолчанию это 4096 токенов: прежних 1400 часто не хватало для нескольких объектов и продуктов. Сообщение о достижении длины означает `finish_reason=length`, а не тайм-аут. Увеличение `AI_TIMEOUT_SECONDS` его не устраняет. При необходимости увеличьте `AI_MAX_OUTPUT_TOKENS` с учётом контекстного окна модели или добавляйте объекты поэтапно в том же чате. После изменения `.env` пересоздайте контейнер приложения. Сессионные и суточные квоты настраиваются отдельно.

## Геокодирование

Поиск сначала проверяет локальный `geological-objects.json`: названия, синонимы, типы, ориентировочные точки и ссылки на источники. Начальный набор содержит 7 российских объектов, в том числе бывшие карьеры Старая Линза и Тальков Камень. Он не является полным реестром месторождений. Данные точек взяты из Wikidata (CC0); происхождение и ограничения указаны у каждого объекта. Для расширения добавьте запись с уникальным id, русским названием, aliases, kind, region, point `[долгота, широта]`, coordinate_note, source_url и source_name, затем пересоберите образ. Координаты нужно проверять по источнику; десятичные знаки сами по себе не устанавливают точность.

Если локальных совпадений нет, используется Nominatim-совместимый `/search`, а при пустом ответе или недоступности — Wikidata Action API `wbsearchentities` → пакетный `wbgetentities` с координатами P625 Земли. Обратный поиск использует Nominatim `/reverse`. Варианты с источниками показываются пользователю; при неоднозначности модель не должна выбирать объект молча. Внешние поиски включаются после заполнения `GEOCODER_USER_AGENT` именем сервиса и настоящим контактным URL/email. Без него работает локальный справочник и выбор области на карте. Ключи геокодирования не требуются. Полнота российского геологического покрытия и фактический статус отработки не гарантируются.

Внешние HTTP-запросы проходят через общий шлюз PostgreSQL не чаще одного в 1,1 секунды, включая оба обращения Wikidata. Ответы кэшируются на семь дней. На сессию допускается 8 поисков в минуту, запросы не выполняются на каждое нажатие клавиши. При HTTP 429/503 от Wikimedia учитывается Retry-After с временной блокировкой повторов. Запрос из чата может открыть поиск по предложенному названию; спутниковые файлы и текст всего диалога геокодеру не передаются. [Nominatim Usage Policy](https://operations.osmfoundation.org/policies/nominatim/), [поиск](https://nominatim.org/release-docs/latest/api/Search/), [Wikidata API](https://www.wikidata.org/wiki/Wikidata:Data_access), [Wikimedia API rate limits](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits)

`GEOCODER_URL` позволяет переключить Nominatim-совместимого поставщика без изменения кода. Прочие форматы API требуют отдельного адаптера. Geoapify даёт бесплатный тариф 3000 credits в сутки и требует регистрации и ключа. Для публичного проекта это кандидат на замену при росте нагрузки. [Geoapify Geocoding](https://www.geoapify.com/geocoding-api/)

## Вход и телеметрия

Создайте web-приложение в Яндекс OAuth с разрешением `login:info` и Redirect URI `<APP_URL>/auth/callback`. Заполните `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`. На хостинге `APP_URL` должен содержать фактический HTTPS-адрес сервиса, без завершающего слэша. Этот адрес также используется для проверки Origin в POST-запросах. После первого входа пользователь видит свой числовой ID. Добавьте нужные ID через запятую в `ADMIN_YANDEX_IDS`. Также поддерживается точный логин аккаунта Яндекса (без почтового домена): он проверяется только по ответу OAuth API, а не по пользовательской форме. Числовой ID предпочтителен как устойчивый идентификатор. Примените `.env` через `docker compose up -d --force-recreate sputnik`. Если сессия создана до появления проверки логина, интерфейс покажет ссылку «Повторить вход через Яндекс». До повторного входа она сохраняет обычные квоты. После входа роль явно обозначена «Администратор · без квот». Токен Яндекса не сохраняется. [Authorization Code](https://yandex.ru/dev/id/doc/ru/codes/code-url), [профиль пользователя](https://yandex.ru/dev/id/doc/ru/user-information)

Кнопка «Телеметрия» доступна администратору. Она показывает число запросов и ошибок, токены по `usage`, неразрешённые резервы, длительности ответов и обращения к каталогу по продуктам. Тексты задач и координаты хранятся только в сессии для продолжения диалога. В события телеметрии, журналы запросов ИИ и статистику обращения к каталогу они не копируются. Технические события очищаются через `TELEMETRY_DAYS`, истёкшие сессии — при ежедневной очистке во время активности сервиса. Очищение cookie создаёт новую сессию, но общий суточный лимит и ограничение сетевого адреса продолжают действовать.

Перед первым сообщением показаны условия передачи текста, координат и метаданных модели. При `AI_LOCAL_MODE=true` панель указывает локальную Ollama; при облачном подключении — передачу в облако и ответственность пользователя за предоставленные сведения. Подтверждение хранится в сессии и запрашивается заново при смене адреса или режима модели. Снимки и файлы в запрос модели не включаются.

## Проверка

`assistant-cases.json` задаёт 12 предметных сценариев с ожидаемыми продуктами, уточнениями, ограничениями и запрещёнными утверждениями. Это рубрика для оценки настоящей модели, а не измеренный результат её работы.

Автоматические проверки выполняются на отдельном Compose-проекте и отдельном томе PostgreSQL. Флаг `SPUTNIK_TEST_DATABASE=1` разрешает тестам очищать таблицы в этом хранилище.

```sh
docker compose --env-file example.env -p sputnik-tests up --build -d --wait
docker compose --env-file example.env -p sputnik-tests run --rm --no-deps -v "$(pwd)/tests:/tests:ro" -e SPUTNIK_TEST_DATABASE=1 sputnik python -m unittest discover -s /tests -v
docker compose --env-file example.env -p sputnik-tests down -v
```

Перед запуском освободите порт из `example.env` или задайте отдельный `SPUTNIK_PORT` для тестового проекта. Автотесты проверяют реальный PostgreSQL, атомарность лимитов, OAuth state, защиту POST, пересечения полигонов, согласование токенов и обработку ответа модели. Облачная модель и Яндекс в них подменены управляемыми ответами; сквозная проверка этих поставщиков требует настроенных ключей.
